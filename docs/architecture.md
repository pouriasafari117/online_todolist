# معماری و همگام‌سازی

## مرز سیستم

یک وب‌اپ ایستا از طریق HTTPS و GitHub REST API به مخزن عمومی `pouriasafari117/online_todolist` متصل می‌شود. نسخهٔ اول تک‌کاربره است و مخزن کد و داده یکی است. توکن فقط با انتخاب صریح همین مخزن در GitHub و با مجوز `Contents: read and write` صادر می‌شود؛ Metadata ممکن است به صورت خودکار فقط خواندنی باشد. سایت نمی‌تواند خودکار مجوز نوشتن بدهد یا انتخاب مخزن و تأیید نهایی کاربر را تضمین کند. هرگز توکن گسترده‌تر به عنوان جایگزین خودکار پیشنهاد نشود. هنگام پیاده‌سازی، قابلیت‌های رابط GitHub و محدودیت‌های شاخه با مستندات رسمی بررسی شوند.

در اجرای محلی سرور نام شاخهٔ checkout را در تنظیمات زمان اجرا قرار می‌دهد؛ در انتشار GitHub Actions نام شاخهٔ منتشرشده به فایل تنظیمات سایت تزریق می‌شود. میزبانی استاتیک بدون این تنظیمات نام شاخه را از کاربر می‌پرسد. سایت شاخهٔ فعال را نمایش می‌دهد و تمام خواندن‌ها و نوشتن‌ها از همان شاخه استفاده می‌کنند. GitHub Pages یک سایت مشترک دارد و آخرین انتشار موفق شاخهٔ فعال را تعیین می‌کند. ادغام فقط داده‌های موجود در commitهای ادغام‌شده را منتقل می‌کند؛ تغییرات بعدی شاخهٔ قدیمی منتقل نمی‌شوند و تعارض‌های Git باید حل شوند. اگر محافظت شاخه جلوی نوشتن را بگیرد، پیام روشن داده شود؛ برنامه نباید آن را دور بزند.

- `data/tasks.json`: دفتر عمومی با schema نسخه‌دار.
- `data/vault.json`: envelope عمومی توکن رمزگذاری‌شده، بدون گذرواژه یا توکن آشکار. خواندن آن در دستگاه تازه بدون اعتبارنامه ممکن است.

هر کسی می‌تواند کارها و envelope را بخواند. توکن دسترسی به کل محتوای همین مخزن دارد، نه فقط این دو فایل. برنامه نباید فرض کند فایل جداگانه مرز مجوز است.

## مدل داده

```json
{
  "schemaVersion": 1,
  "tasks": [{
    "id": "8b166d8b-69c5-4bce-8f5b-37e87150a4e9",
    "title": "خرید نان",
    "description": "",
    "completed": false,
    "priority": "normal",
    "dueDate": null,
    "createdAt": "2026-01-01T12:00:00.000Z",
    "updatedAt": "2026-01-01T12:00:00.000Z"
  }]
}
```

شناسه با `crypto.randomUUID` ساخته شود؛ سررسید `YYYY-MM-DD` و زمان‌ها UTC باشند. ورودی‌ها و اندازه‌ها محدود و اعتبارسنجی شوند. نسخهٔ ناشناخته یا JSON خراب نباید بازنویسی شود؛ قبل از تغییر schema مهاجرت طراحی شود.

## راه‌اندازی و ورود

در اولین راه‌اندازی برنامه وضعیت فایل vault را بررسی می‌کند. تنها پس از تأیید نبود فایل و اعتبارسنجی توکن و مخزن، با رضایت کاربر vault ایجاد می‌شود؛ وجود vault یا پاسخ مبهم نباید به بازنویسی منجر شود. در دستگاه جدید فایل عمومی از شاخهٔ موردنظر خوانده می‌شود، گذرواژه به صورت محلی رمزگشایی می‌کند و توکن با API اعتبارسنجی می‌شود. گذرواژه هرگز به GitHub ارسال نمی‌شود. نبود فایل، رمز اشتباه، دادهٔ خراب، توکن لغوشده و خطای شبکه به شکل مناسب مدیریت شوند. به دلیل تاریخچهٔ عمومی، بازنویسی vault نسخه‌های قدیمی را پاک نمی‌کند.

## ذخیرهٔ کارها

- Contents API فایل و blob SHA را می‌خواند؛ 404 تنها پس از بررسی مخزن، شاخه و نبود فایل، دفتر تازه محسوب می‌شود. خطای دسترسی نباید فایل خالی بسازد.
- تغییرات در حافظه اعمال و در انتظار نمایش داده شوند؛ نوشتن‌ها سریالی و با debounce تجمیع شوند. PUT محتوای کامل و SHA مبنا را می‌فرستد؛ برای ایجاد فایل SHA حذف می‌شود. موفقیت فقط پس از تأیید API و ثبت SHA جدید نمایش داده شود.
- هنگام تعارض SHA، ذخیره متوقف می‌شود؛ کاربر می‌تواند نسخهٔ محلی را به صورت JSON دریافت کند یا با تأیید، نسخهٔ GitHub را جایگزین کند. ادغام سه‌طرفهٔ خودکار هنوز پیاده‌سازی نشده است؛ هیچ نسخه‌ای بی‌صدا برنده نمی‌شود.
- پس از قطع ارتباط در حین PUT، پیش از تکرار ابتدا نتیجه از مخزن خوانده و بررسی شود. خطاهای شبکه، محدودیت نرخ، انقضا، مجوز و محافظت شاخه پیام جداگانه دارند. تغییرات معلق فقط در حافظه‌اند و با بستن صفحه ممکن است از دست بروند؛ هنگام خروج هشدار داده شود.

GitHub محدودیت نرخ و اندازه دارد و برای بار سنگین تضمین مناسبی نیست. سایت از HTTPS و URLهای سازگار با میزبان استاتیک استفاده می‌کند؛ هیچ کد مرورگر به localhost وابسته نباشد.
