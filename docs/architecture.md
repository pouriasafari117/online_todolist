# معماری و همگام‌سازی

## مرز سیستم

یک وب‌اپ ایستا از طریق HTTPS و GitHub REST API به مخزن عمومی `pouriasafari117/online_todolist` متصل می‌شود. نسخهٔ اول تک‌کاربره است و مخزن کد و داده یکی است. توکن فقط با انتخاب صریح همین مخزن در GitHub و با مجوز `Contents: read and write` صادر می‌شود؛ Metadata ممکن است به صورت خودکار فقط خواندنی باشد. سایت نمی‌تواند خودکار مجوز نوشتن بدهد یا انتخاب مخزن و تأیید نهایی کاربر را تضمین کند. هرگز توکن گسترده‌تر به عنوان جایگزین خودکار پیشنهاد نشود. هنگام پیاده‌سازی، قابلیت‌های رابط GitHub و محدودیت‌های شاخه با مستندات رسمی بررسی شوند.

تمام اجراها، از جمله پیش‌نمایش و اجرای محلی، داده‌ها را فقط از شاخهٔ `main` می‌خوانند و در همان شاخه می‌نویسند؛ صفحهٔ انتخاب شاخه حذف شده است. داده‌های شاخه‌های دیگر به‌طور خودکار منتقل نمی‌شوند. انتشار GitHub Pages از طریق Actions فقط از `main` انجام می‌شود. اگر محافظت شاخه جلوی نوشتن را بگیرد، پیام روشن داده شود؛ برنامه نباید آن را دور بزند.

- `data/tasks.json`: دفتر عمومی با schema نسخه‌دار.
- `data/vault.json`: envelope عمومی توکن رمزگذاری‌شده، بدون گذرواژه یا توکن آشکار. خواندن آن در دستگاه تازه بدون اعتبارنامه ممکن است.

هر کسی می‌تواند کارها و envelope را بخواند. توکن دسترسی به کل محتوای همین مخزن دارد، نه فقط این دو فایل. برنامه نباید فرض کند فایل جداگانه مرز مجوز است.

## مدل داده

فایل `data/tasks.json` از schema نسخهٔ ۲ استفاده می‌کند: `tasks` کارهای روز جاری و کارهای معمولی را نگه می‌دارد، `dailyTemplates` فهرست کارهای ثابت و تاریخ شروعشان است، `currentDay` روز جاری دفتر و `history` تصویر وضعیت کارها در پایان روزهای قبلی است. قالب نسخهٔ ۱ با حفظ کارها به نسخهٔ ۲ تبدیل می‌شود و برای روزهای پیش از ارتقا، تاریخچه‌ای جعل نمی‌شود. شناسهٔ کار روزانه با شناسهٔ الگو و تاریخ تعیین می‌شود. تغییر یا حذف الگو از روز بعد اثر دارد و نسخهٔ امروز یا تاریخچه را تغییر نمی‌دهد.

روز بر اساس منطقهٔ زمانی `Asia/Tehran` تعیین می‌شود. هنگام بازشدن دفتر، بازگشت به صفحه و طی اجرای برنامه، روزهای گذشته به ترتیب ثبت و کارهای ثابت برای روز جدید ناتمام ایجاد می‌شوند؛ در روزهایی که برنامه باز نشده، نمونه‌های روزانه ناتمام و کارهای معمولی با آخرین وضعیت شناخته‌شده ثبت می‌شوند. ساعتی که از تاریخ دفتر عقب‌تر باشد خطا می‌دهد و اطلاعات بازنویسی نمی‌شود. در صورت تعارض SHA تغییرات متوقف می‌شوند. محدودیت حجم ۷۵۰ کیلوبایت و حد ۳۶۶۰ روز به جای حذف بی‌صدا، باعث توقف و پیام خطا می‌شوند.

## راه‌اندازی و ورود

در اولین راه‌اندازی برنامه وضعیت فایل vault را بررسی می‌کند. تنها پس از تأیید نبود فایل و اعتبارسنجی توکن و مخزن، با رضایت کاربر vault ایجاد می‌شود؛ وجود vault یا پاسخ مبهم نباید به بازنویسی منجر شود. در دستگاه جدید فایل عمومی از شاخهٔ اصلی خوانده می‌شود، گذرواژه به صورت محلی رمزگشایی می‌کند و توکن با API اعتبارسنجی می‌شود. گذرواژه هرگز به GitHub ارسال نمی‌شود. نبود فایل، رمز اشتباه، دادهٔ خراب، توکن لغوشده و خطای شبکه به شکل مناسب مدیریت شوند. به دلیل تاریخچهٔ عمومی، بازنویسی vault نسخه‌های قدیمی را پاک نمی‌کند.

## ذخیرهٔ کارها

- Contents API فایل و blob SHA را می‌خواند؛ 404 تنها پس از بررسی مخزن، شاخه و نبود فایل، دفتر تازه محسوب می‌شود. خطای دسترسی نباید فایل خالی بسازد.
- تغییرات در حافظه اعمال و در انتظار نمایش داده شوند؛ نوشتن‌ها سریالی و با debounce تجمیع شوند. PUT محتوای کامل و SHA مبنا را می‌فرستد؛ برای ایجاد فایل SHA حذف می‌شود. موفقیت فقط پس از تأیید API و ثبت SHA جدید نمایش داده شود.
- هنگام تعارض SHA، ذخیره متوقف می‌شود؛ کاربر می‌تواند نسخهٔ محلی را به صورت JSON دریافت کند یا با تأیید، نسخهٔ GitHub را جایگزین کند. ادغام سه‌طرفهٔ خودکار هنوز پیاده‌سازی نشده است؛ هیچ نسخه‌ای بی‌صدا برنده نمی‌شود.
- پس از قطع ارتباط در حین PUT، پیش از تکرار ابتدا نتیجه از مخزن خوانده و بررسی شود. خطاهای شبکه، محدودیت نرخ، انقضا، مجوز و محافظت شاخه پیام جداگانه دارند. تغییرات معلق فقط در حافظه‌اند و با بستن صفحه ممکن است از دست بروند؛ هنگام خروج هشدار داده شود.

GitHub محدودیت نرخ و اندازه دارد و برای بار سنگین تضمین مناسبی نیست. سایت از HTTPS و URLهای سازگار با میزبان استاتیک استفاده می‌کند؛ هیچ کد مرورگر به localhost وابسته نباشد.
