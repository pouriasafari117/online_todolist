# نقشهٔ راه و معیارهای پذیرش

این سند طرح پیشنهادی است؛ هیچ مرحله‌ای در مخزن فعلی پیاده‌سازی یا تأیید نشده است.

## ۱. پایه و رابط

انتخاب فناوری سبک برای سایت ایستا، راه‌اندازی تست و استقرار HTTPS، طراحی فارسی RTL و واکنش‌گرا، گرادیان آرام و حالت کاهش حرکت. معیار پذیرش: رابط با صفحه‌کلید قابل استفاده باشد و روی موبایل و دسکتاپ خوانا بماند.

## ۲. اتصال و خزانه

راهنمای ساخت مخزن خصوصی و توکن محدود، اعتبارسنجی هویت و مخزن، خزانهٔ محلی و قفل/بازکردن، تغییر گذرعبارت و خروج. معیار پذیرش: توکن در مخزن، URL یا لاگ نباشد؛ ciphertext با گذرعبارت اشتباه یا دستکاری‌شده باز نشود؛ تغییر گذرعبارت پس از شکست، رکورد قبلی را از بین نبرد؛ دستگاه جدید نیاز به توکن داشته باشد.

## ۳. دفتر و همگام‌سازی

مدل نسخه‌دار، عملیات کارها، فیلترها و اتصال Contents API با SHA، صف نوشتن و حل تعارض. معیار پذیرش: تغییرات از دو دستگاه همگام شوند، تعارض مبهم بدون انتخاب کاربر داده را از بین نبرد، خطاهای شبکه و مجوز وضعیت ذخیره‌نشده را حفظ کنند، فایل نامعتبر بازنویسی نشود.

## ۴. سخت‌سازی و انتشار

آزمایش واحد رمزگذاری و مدل، آزمون یکپارچهٔ API با پاسخ‌های شبیه‌سازی‌شده، تست دستی با دو مرورگر و مخزن خصوصی آزمایشی، بازبینی دسترس‌پذیری و امنیت و مستندات استقرار. سناریوها شامل 404 مبهم، محدودیت نرخ، قطع ارتباط پس از PUT، انقضای توکن، تغییر هم‌زمان، عمومی شدن مخزن، دادهٔ خراب و پاک‌شدن حافظهٔ مرورگر باشند. انتشار تنها پس از تأیید صریح کاربر و بررسی سیاست میزبان.

## تصمیم‌های آینده

اگر ورود واقعاً با رمز عبور روی دستگاه جدید ضروری باشد، باید سرویس هویت/ذخیره‌سازی یا طراحی بازیابی مستقل با ارزیابی تهدید، هزینه و عملیات پذیرفته شود؛ یا مدل عمومیِ ciphertext و خطر حدس آفلاین آگاهانه بررسی شود. GitHub App/OAuth نیز به جریان مجوز و احتمالاً زیرساخت پشتیبان نیاز دارد و جایگزین بی‌هزینه و خودکار PAT نیست. هیچ‌کدام جزو تعهدات نسخهٔ اول نیستند.
