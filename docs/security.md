# طراحی امنیت و محدودیت‌های بنیادی

## تهدیدها و تصمیم‌ها

توکن یک کلید دسترسی است: هر شخص یا کدی که آن را به دست آورد تا زمان انقضا یا لغو، در محدودهٔ مجوزهای آن قدرت دارد. فایل هر کاربر در مخزن مشترک مانع خواندن، تغییر یا حذف توسط سایر دارندگان دسترسی نوشتن نمی‌شود؛ حتی فایل رمزنگاری‌شده نیز از حذف یا جایگزینی در امان نیست. بنابراین مخزن خصوصی مستقل، توکن محدود و عدم ذخیرهٔ توکن در مخزن، تصمیم پایه‌اند.

رمزگذاری توکن با گذرعبارت و قرار دادن ciphertext در مخزن عمومی، بازیابی روی دستگاه جدید را ممکن می‌کند اما هر بازدیدکننده می‌تواند حملهٔ حدس آفلاین انجام دهد؛ همچنین نویسندگان می‌توانند داده را حذف یا جایگزین کنند. قرار دادن آن در مخزن خصوصی نیز مشکل بوت‌استرپ دارد: دستگاه جدید برای خواندن همان فایل ابتدا به اعتبارنامه نیاز دارد. بدون سرویس واسط یا راز اولیهٔ مستقل، ورود بین‌دستگاهی فقط با رمز عبور به مخزن خصوصی ممکن نیست. هش رمز عبور هم مجوز GitHub تولید نمی‌کند. در نسخهٔ اول این قابلیت وعده داده نمی‌شود.

مخزن خصوصی رمزنگاری سرتاسری نیست. GitHub و اعضای مجاز مخزن به محتوای کارها دسترسی دارند؛ commitهای قدیمی هم ممکن است داده‌های حذف‌شده را حفظ کنند. برای اسرار یا اطلاعات حساس مناسب نیست. حتی اگر داده‌ها رمز شوند، متادیتا و تاریخچه ممکن است آشکار بمانند.

## خزانهٔ محلی پیشنهادی

توکن فقط با رضایت کاربر، در مرورگر همان دستگاه به شکل رمز‌شده در IndexedDB ذخیره شود. گذرعبارت یا هش قابل استفاده به عنوان تأییدکننده جداگانه ذخیره نشود؛ موفقیت رمزگشایی و اعتبارسنجی قالب، آزمون باز شدن قفل است. از Web Crypto استاندارد استفاده شود، نه الگوریتم اختصاصی:

- کلید با PBKDF2-HMAC-SHA-256، salt تصادفی ۱۶ بایتی و تعداد تکرار نسخه‌بندی‌شده مشتق شود؛ مقدار اولیه حداقل ۶۰۰٬۰۰۰ و روی دستگاه‌های هدف از نظر کارایی و توصیه‌های روز بازبینی شود. گذرعبارت طولانی و یکتا تشویق شود؛ KDF مقاومت گذرعبارت ضعیف را تضمین نمی‌کند.
- AES-256-GCM با IV تصادفی تازهٔ ۱۲ بایتی برای هر رمزگذاری و tag کامل ۱۲۸ بیتی؛ نسخه و پارامترهای قالب به صورت دادهٔ تأییدشده (AAD) متصل شوند. از `crypto.getRandomValues` استفاده شود. نسخه، الگوریتم، salt، تعداد تکرار، IV و ciphertext/tag در envelope ذخیره شوند؛ توکن و گذرعبارت هرگز در متن آشکار ذخیره نشوند.
- پارامترهای envelope قبل از KDF با حدود مجاز اعتبارسنجی شوند تا دادهٔ خراب باعث مصرف منابع نامحدود نشود. خطای رمزگشایی پیام عمومی داشته باشد. Web Crypto و ذخیره‌سازی در محیط امن HTTPS لازم‌اند.
- بازکردن قفل توکن را موقتاً در حافظه نگه می‌دارد؛ قفل دستی، خروج و پایان نشست ارجاع‌ها را پاک کنند. جاوااسکریپت تضمین پاک‌سازی امن حافظه نمی‌دهد. ذخیرهٔ مرورگر قابل حذف یا استخراج است و در برابر بدافزار، افزونهٔ مخرب، دستگاه باز یا XSS حفاظت کامل ندارد.
- تغییر گذرعبارت: ابتدا رمز قبلی را اعتبارسنجی و توکن را رمزگشایی کن، سپس با salt و IV تازه و پارامترهای جاری دوباره رمزگذاری کن؛ جایگزینی رکورد به صورت تراکنشی فقط پس از موفقیت انجام شود. تغییر قفل محلی روی دستگاه‌های دیگر اعمال نمی‌شود و توکن GitHub را نمی‌چرخاند. فراموشی گذرعبارت بازیابی ندارد؛ رکورد محلی پاک و توکن جدید یا موجود دوباره وارد شود.

## چرخهٔ توکن و رابط

توکن را هرگز در URL، commit، لاگ، تحلیل، گزارش خطا، clipboard خودکار یا پیام خطای خام قرار ندهید. درخواست‌ها فقط به میزبان مورد انتظار GitHub و از طریق HTTPS ارسال شوند؛ تغییر مسیر غیرمنتظره نباید اعتبارنامه را به مبدأ دیگر بفرستد. ورودی رمزگونه باشد، نمایش اختیاری با هشدار، و پس از استفاده پاک شود. خروج از دستگاه رکورد محلی را حذف می‌کند ولی توکن را در GitHub لغو نمی‌کند؛ راهنمای لغو و ساخت توکن جدید در تنظیمات ارائه شود. انقضا، مجوز ناکافی، لغو و نیاز به جایگزینی صریحاً مدیریت شوند. لینک راهنما باید به صفحات رسمی GitHub برود و کاربر قبل از تأیید نهایی مجوزها را بررسی کند.

## امنیت زنجیرهٔ انتشار

وب‌اپ ایستا هنگام ورود توکن به کد تحویل‌داده‌شده اعتماد می‌کند؛ XSS یا تغییر مخرب کد منتشرشده می‌تواند توکن را بدزدد، حتی اگر خزانه قوی باشد. متن کارها فقط به صورت متن رندر شود؛ HTML خام و اجرای محتوای کاربر ممنوع. وابستگی‌ها حداقلی و قفل‌شده، بازبینی و به‌روزرسانی شوند. از اسکریپت، فونت و تحلیل شخص ثالث اجتناب شود. CSP محدودکننده با `connect-src` فقط مبدأهای لازم، منع اسکریپت inline تا حد امکان، و سایر هدرهای امنیتی در میزبان پشتیبانی‌شده تنظیم و آزمایش شوند؛ محدودیت‌های GitHub Pages برای هدرها باید بررسی شود و CSP جایگزین بازبینی کد نیست. دسترسی انتشار، محافظت شاخه، بازبینی تغییرات و امنیت حساب مالک سایت مهم‌اند. هیچ ادعای امنیت مطلق یا «بهترین رمزنگاری» بدون پیاده‌سازی و ممیزی مستقل قابل اتکا نیست.
