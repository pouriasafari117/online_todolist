# امنیت و مدیریت توکن

## تصمیم و محدوده

مالک آگاهانه پذیرفته که کارهای نسخهٔ اول عمومی باشند و توکن رمزگذاری‌شده در تاریخچهٔ عمومی همین مخزن قرار بگیرد تا ورود با گذرواژه در دستگاه جدید ممکن شود. این راهکار برای استفادهٔ شخصی فعلی است و مدل امن میزبانی چند کاربر نیست.

توکن fine-grained باید هنگام ساخت در GitHub با انتخاب **Only select repositories** به `pouriasafari117/online_todolist` محدود شود و فقط مجوز `Contents: read and write` مورد نیاز را داشته باشد (Metadata فقط خواندنی ممکن است خودکار اضافه شود). کاربر باید مالک، مخزن، مجوز و تاریخ انقضا را در صفحهٔ GitHub بررسی و تأیید کند؛ سایت توکن نمی‌سازد و نمی‌تواند محدودیت را از جانب GitHub تضمین کند. در صورت نبود گزینهٔ محدودسازی، به توکن گسترده‌تر تنزل خودکار ندهید.

دارندهٔ توکن می‌تواند محتوای همین مخزن و کد سایت را در محدودهٔ مجوز و قواعد شاخه تغییر دهد. برای همین مخزن عمومی، هر کسی می‌تواند vault را دانلود و گذرواژه را آفلاین حدس بزند؛ محدودیت نرخ ورود در سایت جلوی آن را نمی‌گیرد. گذرواژه باید طولانی، تصادفی و یکتا باشد. هرگز توکن یا گذرواژه در چت، URL، لاگ یا کد ذخیره نشود.

## دکمهٔ ساخت توکن

دکمه به [فرم رسمی از پیش پرشدهٔ GitHub](https://github.com/settings/personal-access-tokens/new?name=Online%20Todo%20List&target_name=pouriasafari117&contents=write&expires_in=90) می‌رود. GitHub از پارامترهای نام، مالک، مجوز و انقضا پشتیبانی می‌کند؛ `contents=write` مجوز خواندن و نوشتن محتوا را درخواست می‌کند. طبق [مستندات GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#pre-filling-fine-grained-personal-access-token-details-using-url-parameters)، انتخاب یک مخزن مشخص پارامتر پشتیبانی‌شده‌ای در این فرم ندارد. بنابراین برنامه نباید ادعا کند مخزن را خودکار انتخاب کرده است: کاربر باید **Only select repositories** و سپس `online_todolist` را در خود GitHub انتخاب و تولید توکن را تأیید کند. پس از ساخت نیز توکن را در سایت وارد می‌کند؛ GitHub آن را خودکار به سایت ارسال نمی‌کند.

برنامه می‌تواند صحت هویت و دسترسی لازم به این مخزن را بررسی کند، اما این بررسی به‌تنهایی ثابت نمی‌کند توکن به مخازن دیگر دسترسی ندارد. تأیید محدود بودن انتخاب در فرم GitHub بر عهدهٔ کاربر است. مخازن عمومی دیگر همچنان مانند همیشه قابل خواندن عمومی‌اند؛ هدف، ندادن دسترسی اضافی توکن به مخازن دیگر است.

## قالب vault پیشنهادی

در مرورگر و فقط با Web Crypto استاندارد:

- کلید از گذرواژه با PBKDF2-HMAC-SHA-256، salt تصادفی ۱۶ بایتی و تعداد تکرار نسخه‌بندی‌شده مشتق شود؛ مقدار اولیه حداقل ۶۰۰٬۰۰۰ و متناسب با دستگاه‌های هدف و توصیه‌های روز بازبینی شود. KDF گذرواژهٔ ضعیف را ایمن نمی‌کند.
- AES-256-GCM با IV تصادفی تازهٔ ۱۲ بایتی برای هر رمزگذاری و tag کامل ۱۲۸ بیتی؛ نسخه و پارامترهای قالب به صورت دادهٔ تأییدشده (AAD) متصل شوند. از `crypto.getRandomValues` استفاده شود. envelope شامل نسخه، الگوریتم، salt، تعداد تکرار، IV و ciphertext/tag باشد؛ هیچ هش تأییدکنندهٔ جداگانه‌ای برای گذرواژه ذخیره نشود.
- پیش از مشتق‌سازی، پارامترها با حدود مجاز اعتبارسنجی شوند. شکست رمزگشایی پیام عمومی داشته باشد. HTTPS ضروری است. توکن بازشده فقط در حافظه بماند و در قفل یا خروج ارجاع‌ها پاک شوند؛ پاک‌سازی امن حافظه در جاوااسکریپت تضمین نمی‌شود.

## تغییر و بازیابی

برای تغییر گذرواژه، رمز قبلی را تأیید و توکن را رمزگشایی کنید، سپس با salt و IV تازه و پارامترهای جاری رمزگذاری و با SHA نسخهٔ خوانده‌شده vault را به‌روزرسانی کنید. تعارض یا شکست نباید فایل موجود را بی‌صدا بازنویسی کند. دستگاه‌های دیگر برای باز کردن vault جدید به رمز جدید نیاز دارند، اما دستگاهی که توکن را قبلاً باز کرده ممکن است تا قفل شدن همچنان از آن استفاده کند.

تغییر گذرواژه توکن را لغو نمی‌کند و نسخه‌های قدیمی vault در تاریخچهٔ عمومی باقی می‌مانند؛ کسی که رمز قدیمی را می‌داند ممکن است نسخهٔ قدیمی را باز کند. در صورت افشای احتمالی، توکن قدیمی را در GitHub لغو، توکن محدود جدید صادر و vault را جایگزین کنید. پس از فراموشی گذرواژه، بازیابی آن ممکن نیست؛ توکن قدیمی لغو و vault با توکن و گذرواژهٔ جدید به صورت صریح جایگزین شود. خروج از سایت توکن را در GitHub لغو نمی‌کند. انقضا و لغو باید مسیر جایگزینی مشخصی داشته باشند.

## امنیت اجرا

کد سایت هنگام باز شدن vault به توکن دسترسی دارد؛ XSS، افزونهٔ مخرب یا تغییر مخرب کد منتشرشده می‌تواند آن را بدزدد. کارها فقط به صورت متن رندر شوند، HTML خام و اسکریپت شخص ثالث حذف، وابستگی‌ها حداقلی و قفل‌شده، و تغییرات انتشار بازبینی شوند. CSP محدودکننده و سایر هدرهای امنیتی تا جایی که میزبان پشتیبانی می‌کند تنظیم و آزمایش شوند. فقط به مبدأهای مورد انتظار GitHub درخواست اعتباردار ارسال شود. هیچ ادعای امنیت مطلق یا ممیزی‌نشده مطرح نشود.
